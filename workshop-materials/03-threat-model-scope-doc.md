# GameVault —— 内购与金币发放设计文档 / Scope Doc(Threat Modeling 输入)

> **用途**:作为 **Module 2 威胁建模** 的 **scope doc** 上传,把分析聚焦在"内购发币 + 分数上榜"这两个
> 价值敏感特性上;可同时连接源码仓库作为上下文。客户也可换成自己的特性设计文档。

## 特性:内购发币(IAP)与分数上榜(Leaderboard)

### 目标
让玩家完成内购后获得游戏金币,并把对局分数提交到全服排行榜。

### 参与者与信任边界
- **匿名用户**:仅能看公开排行榜。
- **已登录玩家**:提交分数、确认内购、查看资料。
- **运营/GM**:发放金币、封禁玩家、查看全部玩家。
- **信任边界**:游戏客户端(不可信,可能被 root/越狱/注入外挂) ↔ Express API(可信) ↔ PostgreSQL(可信,同 VPC) ↔ S3 ↔ 应用商店支付(外部)。

### 关键流程
1. 玩家在应用商店完成支付,客户端拿到收据(receipt)。
2. 客户端调用 `POST /iap/confirm`,body 含 `productId`、`coins`(声称到账数)、`receipt`。
3. 后端给该玩家加币并返回余额。
4. 对局结束,客户端调用 `POST /scores` 提交 `score`。
5. 任何人可 `GET /leaderboard/search?q=` 搜索排行榜。
6. GM 通过 `/admin/*` 发币、封号、查看玩家。

### 关键数据
- 玩家凭证(口令哈希、JWT)
- 金币余额、VIP 等级、充值记录
- 排行榜分数(影响赛季奖励)
- 玩家 PII(邮箱)

### 当前实现要点(供 agent 理解现状)
下面只描述可运行 API;S3/应用商店是设计上下文,原型没有真实连接。所有账户和支付数据均为虚构。

- JWT 密钥硬编码;token 无过期。
- `iap/confirm` 不校验收据,信任客户端 `coins`。
- `scores` 信任客户端 `score`。
- `players/:id` 不校验归属。
- `/admin/*` 无角色校验。
- 登录/内购/提交分数无限流;无审计日志;错误堆栈直接返回。

### 希望评估的问题
- 攻击者能否不花钱获得金币、或刷榜获取赛季奖励?
- 能否冒充他人/管理员、读取他人账号、或越权发币封号?
- 哪些价值敏感环节缺少服务端校验与可追溯性?
